## 第 1 章 仓库与代码库介绍（HistoryHub）

> 本章写给第一次拿到本仓库的人：它是什么、基于哪个版本、怎么跑起来。功能使用说明见「一 ~ 十」章，开发边界见第十章（Z 编号）。

### 1.1 一句话定位

**HistoryHub** 是大模型聚合平台 [QuantumNous/new-api](https://github.com/QuantumNous/new-api) 的**网页聊天前端 + 历史记录中心**。它不改动上游主体，而是以一个自包含插件目录 `0/`（Go 包名 `historyhub`）并入 new-api 源码树：**同一个二进制、同一个进程、两个端口**

- 主服务（管理台 + API 网关）：默认 `127.0.0.1:3000`（仅本机回环，`--ipPortMain` 可改）；
- HistoryHub 网页端：默认 `0.0.0.0:3001`，浏览器直接访问（`--ipPortHyb` 可改）。

| 核心能力 | 说明 | 详见 |
|---|---|---|
| 网页对话 | 流式/非流式输出、思考过程、图片与文本附件 | 第三章 B |
| 历史回放 | 会话分组列表、逐轮回放、API 直连会话统一展示 | 第四章 C |
| 搜索与高亮 | 问题/答案双向检索（AND/引号/竖线/排除/日期）、命中高亮 | 第五章 D |
| API 密钥 | 网页端自建/管理 `sk-` 密钥（额度/模型/IP 白名单） | 第六章 E |
| 钱包 | 余额与消费流水只读展示 | 第七章 F |

## 一、总述

### 1.1 这是什么

New-API（大模型聚合平台）新增了一套面向普通用户的**网页聊天前端 historyhub**，与主服务编译为**同一个二进制、运行在同一个进程**：

- 主服务（原 New-API 管理台与 API 网关）：默认 `:3000`；
- historyhub 网页端（本说明书主角）：默认 `:3001`，浏览器访问 `http://<服务器>:3001/` 即可使用。

普通用户只需要记两个概念：

| 概念 | 说明 |
|---|---|
| **网页对话** | 登录 :3001 后在网页上直接和模型聊天，聊天记录自动保存 |
| **API 密钥直连** | 不登录网页，把 `sk-` 密钥填进 openclaw / hermes / codex 等 agent 工具里直接调用模型，调用记录同样自动保存 |

两条链路走的是**同一条记录通道**：无论哪种方式，每轮问答都会写入「会话-消息」库（可搜索、可回放）并落盘日志文件，系统提示词、图片附件的处理逻辑也完全一致。

### 1.2 架构总览

```mermaid
flowchart LR
    subgraph client["客户端"]
        B["浏览器<br/>网页聊天 / 搜索 / 密钥 / 钱包"]
        A["Agent 工具<br/>openclaw / hermes / codex"]
    end
    subgraph oneproc["同一进程（一个二进制）"]
        H[":3001 historyhub<br/>网页前端 + 记录代理"]
        M[":3000 主服务<br/>计费 / 渠道 / 上游"]
    end
    U[("主库 one-api.db<br/>users / tokens / logs")]
    S[("hybdb 会话分片库<br/>sen / msg / 附件")]
    L[("hyblog 日志文件")]
    B -->|"登录 + /hybapi/*"| H
    A -->|"sk- 密钥 /v1/*"| H
    H -->|"内部转发 原样记录"| M
    M -->|"计费/渠道选择"| U
    H --> S
    H --> L
```

要点：

1. agent 与网页**都指向 :3001**——:3001 本身就是完整的 OpenAI 兼容入口（`/v1/chat/completions` 带记录，其余路径透传），使用者不需要知道 :3000 的存在；
2. 记录（会话/消息/附件/日志）全部发生在 :3001 一侧，主服务业务代码零改动（仅 Z02 白名单的 main.go 接线与手机号校验两处例外）；
3. 数据分两类：账号与计费在主库（sqlite），聊天内容在按用户拆分的分片库（`hybdb/u%09d.db`），互不干扰。

### 1.3 快速上手（三步）

1. 浏览器打开 `http://<服务器>:3001/`，输入手机号 + 密码登录；
2. 顶栏选模型、底部输入框发消息，答案逐字流出；
3. 左侧随时翻历史、搜索；左下角用户区可改密码、管密钥、看钱包。

```mermaid
sequenceDiagram
    participant B as 浏览器
    participant H as ":3001 记录代理"
    participant M as ":3000 主服务"

    alt 模型支持流式
        U-->>M: SSE 增量块
        M-->>H: SSE 直通

    else 模型不支持流式(如 GD-LLM-Lite)
        U-->>M: 一整段 JSON 答案
        M-->>H: 空流(只剩 usage 与 DONE)
        H->>H: 检测到空流 零字节放行
        H->>M: 自动改 stream:false 原题重发(复用同一轮记录)
        M-->>H: 完整 JSON 答案
        H-->>B: 整段渲染(无打字机效果)
    end
    H->>H: 补记答案 + 落盘日志
```

### D02 搜索语法

#### D0201 多词 AND（834 / 836）

空格分隔多个词，要求**同时出现在同一轮的同一侧**（同在问题或同在答案）：

![D0201 搜索AND](README.res/D0201-搜索AND.png)

> 上例命中「专辑载体形式的区别」：某一轮的**同一段答案**里同时含「专辑」和「载体」。跨轮（第 1 轮有 A 词、第 3 轮有 B 词）或同轮跨边（问题有 A、答案有 B）都**不**命中。

**D020101 引号短语**：`"两个 词"` 引号内空格保留为整词短语，作为一个条件参与 AND。

#### D0202 排除词 `-词`（835 / 836 按轮）

`GD-LLM -代码` = 至少一轮含 `GD-LLM` **且该轮内不出现** `代码`（其它轮出现不影响）；也支持 `-"整词 短语"`；词中间的 `-` 是字面字符（`CO-2` 可直接搜）；仅排除词 = 保留存在不含该词的轮的会话：

![D0202 搜索排除](README.res/D0202-搜索排除.png)

#### D0203 字段前缀 `问:` `答:` 与 或者 `|`（835 / 836）

`问:天气 答:合肥` = 同一轮里问题含「天气」**且**答案含「合肥」（优先于范围 chips）；裸词内 `|` 分隔候选任一命中即满足，可与其它词组合（`音乐 媒介|载体`）：

![D0203 搜索问答前缀](README.res/D0203-搜索问答前缀.png)

每个条件的完整形式：`[-] [问:|答:] (引号短语 | 裸词[|裸词...])`。

#### D0204 日期筛选（83 / 831-833）

原生日期选择（显示 `26/08/15` 格式；一侧选择后另一侧自动镜像同值，✕ 单侧清除）。日期按「**逐轮对话**」判定：会话必须在范围内**真的发生过至少一轮**才算命中——活动窗口跨过区间、但当天一轮都没有的会话不会出现。日期与关键词分别判定后 AND：

![D0204 日期筛选](README.res/D0204-日期筛选.png)

### E02 密钥设置

#### E0201 设置弹框（94b）

自建密钥行点「设置」打开（`default` 保持 不限额度/不限模型/不限 IP，不可编辑）：

![E0201 密钥设置](README.res/E0201-密钥设置.png)

三项设置与主站同字段、同校验、同执行机制：

- **E020101 额度**：「不限额度」= 跟随账户余额；「限定额度」= 填**美元金额**（如 `5` = $5，内部按 500000 配额=$1 换算）。额度不足被主站预检拒绝的真实报错：`token quota is not enough, token remain quota: ＄0.001000, need quota: ＄0.037500`
- **E020102 可用模型**：「仅允许勾选的模型」= 从与聊天下拉**同源的模型列表勾选**（已限制但已下架的模型名补显，不会被悄悄丢掉）。调用未勾选模型返回：`This token has no access to model mock-xxx`
- **E020103 IP 白名单**：留空=不限；支持**单 IP**（`112.10.22.8`）与**网段**（`192.168.1.0/24`），逗号或换行分隔；不在名单内的来源一律 403：`您的 IP 不在密钥允许访问的列表中`

**保存细节**：切「限定额度」必须填金额（≥0）；开「仅允许勾选」至少勾 1 个；IP 格式错误给具体提示（`IP 白名单格式不对：abc（支持 IP 如 1.2.3.4 或网段如 10.0.0.0/8）`）。保存即生效（令牌缓存自动失效）。上限同主站：密钥名称 ≤50 字符、最多勾选 100 个模型、IP 白名单最多 100 条、单密钥额度上限 $10 亿。

**对公网 agent 按真实 IP 生效**：入口在 :3001 时主服务只能看到 127.0.0.1，因此 :3001 先按真实来源 IP 校验一次，转发时附带真实 IP 让主服务复检；伪造 `X-Forwarded-For` 无法绕过（:3001 与主服务同一套受信代理配置）：

```mermaid
flowchart TD
    A["agent 请求 :3001 /v1/*"] --> B["取 sk- 密钥对应令牌"]
    B --> C{令牌设了 IP 白名单?}
    C -->|否| F
    C -->|是| D["真实来源 IP 在名单内?<br/>单IP精确比 / 网段CIDR包含"]
    D -->|否| E["403 您的 IP 不在密钥允许访问的列表中"]

```

```bash
curl http://127.0.0.1:3001/v1/chat/completions \
  -H "Authorization: Bearer sk-ixqr........3gP7" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k2.5",
    "stream": false,
    "messages": [{"role":"user","content":"每天早上8点汇总昨天的工单并邮件给负责人"}]

```

## 十、开发边界与禁令（Z 编号）

> 本章是**必须遵守的开发红线**，源自项目原始约束（原 N/E 编号）与历次开发中用户明确定的边界。本章统一使用 Z 编号（映射规则见文首「功能编号体系」），全章只有这一套编号。任何后续改动先对照本章。

## 附录 A：环境变量与启动参数

### A.1 参数总表

0 目录新增的 6 个参数，命令行 flag 与环境变量**同名**（驼峰式），通用优先级：**flag > 环境变量 > 内置默认**。

| 参数（flag） | 环境变量 | 默认 | 作用与要点 | 示例 |
|---|---|---|---|---|
| `--ipPortMain` | `ipPortMain` | `127.0.0.1:3000` | 主服务监听地址（仅回环）；同时决定 :3001 回源端口——改端口只改它 | `--ipPortMain 127.0.0.1:13000` |
| `--ipPortHyb` | `ipPortHyb` | `0.0.0.0:3001` | 网页端第二监听，同进程同二进制 | `--ipPortHyb 0.0.0.0:13001` |
| `--proxy` | `proxy`/`PROXY` | `http://172.17.0.1:57890` | 出站代理，主站中继与 :3001 回源共用；`none` 直连；本机回环永不过代理 | `--proxy none` |
| `--maxConnsPerHost` | `maxConnsPerHost` | `0`（不限） | :3001→主服务并发连接硬上限；首请求时构建 client，改需重启 | `--maxConnsPerHost 128` |
| `--aModelTTLSeconds` | `aModelTTLSeconds` | `300` | 「渠道名/模型名」标签缓存 TTL（秒）；历史行不回溯；首次使用时构建，改需重启 | `--aModelTTLSeconds 60` |
| `--dbMaxOpen` | `dbMaxOpen` | `1000` | 每用户分片库 LRU 常驻连接上限，防 fd 耗尽；超限关最久未用，下次自动重开（无损） | `--dbMaxOpen 2000` |

另有继承自父项目的启动项：`--port`（主站端口，默认 3000）、`PORT` 环境变量（优先于 `--port`）、`--log-dir`、`--version`、`--help`。

### A.2 启动方式、优先级与细节

**三种启动方式**（效果等价程度不同，任选/混用）：
```bash
# ① 纯 flag（--参数 值 与 --参数=值 两种写法等价）
./new-api.exe --ipPortMain 127.0.0.1:3000 --ipPortHyb 0.0.0.0:3001 --proxy none --maxConnsPerHost 128 --aModelTTLSeconds 600 --dbMaxOpen 2000

# ② 纯环境变量
ipPortMain=127.0.0.1:3000 ipPortHyb=0.0.0.0:3001 proxy=none maxConnsPerHost=128 aModelTTLSeconds=600 dbMaxOpen=2000 ./new-api.exe

# ③ 混合：两者都设时 flag 赢
aModelTTLSeconds=900 ./new-api.exe --aModelTTLSeconds 60    # 实际生效 60
```

**主服务监听地址的解析链**（逐级回退）：
`--ipPortMain`/`ipPortMain`（整串生效，含端口）→ `127.0.0.1:` + `PORT` 环境变量 → `127.0.0.1:` + `--port`（默认 3000）。
注意：**只设 `PORT` 或只设 `--port` 时，主服务会换端口监听，但 :3001 的回源仍拨默认端口**——改端口请一律用 `--ipPortMain`，让它同时管两头。

**其它细节**：
- 传 `0` 视为「未指定」回退环境变量/默认值，因此不能用 `--maxConnsPerHost 0` 强行清掉一个非零的同名环境变量（默认本就是 0/不限，实际无影响）。
- `--proxy` 的环境变量大小写都认（`proxy`/`PROXY`），其余参数的 env 必须与表中小写驼峰完全一致。
- 三个数值参数（maxConnsPerHost/aModelTTLSeconds/dbMaxOpen）均为**首次使用时读取**（懒加载），运行中不会热更新，修改后须重启进程。
- Go flag 解析遇到第一个非 flag 参数或单独的 `--` 即停止，后续内容不再当参数解析。
- `./new-api.exe -h` 打印 flag 包完整参数清单（含本表全部 flag）；`--help` 是父项目自定义简介（不含完整清单）。
- 与运行环境相关的其它环境变量：`SQLITE_PATH`（sqlite 主库文件路径，隔离测试用，见附录 D）、`GIN_MODE=debug`（调试模式）。`TZ` 无效——进程启动即固定 `Asia/Shanghai`（日志按天分文件与全部时间戳均按北京时间，不可用参数变更）。
